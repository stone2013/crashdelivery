# 暴力快递 V0.11 — SUBURBAN

## 部署
完整部署 ZIP 解压后，将里面的 index.html、sw.js、manifest.webmanifest、assets/、icons/、licenses/ 等按原目录结构上传到现有网站根目录。不要只上传 index.html，也不要把 ZIP 本身当作网页。

改动文件 ZIP 用于覆盖完整的 V0.10.5.1 NATIVE DOORS 工程；不适用于早期 V0.5。保留未修改的工业素材与图标。无需同时覆盖两种包。不会修改 GitHub 仓库，也不需要更改 TURN 配置。

更新后主界面应显示 V0.11 ONLINE / SUBURBAN，并出现“住宅区已就绪 · 原生门窗投递”。若 PWA 仍为旧版，在主菜单等待新版更新提示后更新；不要清空保存数据。多人各端必须使用本版，协议 crash-delivery-mp011-1。

## 本版内容
22 栋原生 Kenney 住宅：6 个配送住宅 + 16 栋背景住宅。主配送房屋宽约 12.2–15.0 米、高约 7.4–9.9 米；使用原素材的白墙与绿屋顶配色。

101–106 号住宅共有 21 处原生门、车库门及窗户目标。判定坐标来自独立配置的原模型门窗坐标，不是统一取包围盒正中央。不生成任务门、门框或住宅门牌纹理；包裹进入对应原生门窗前的判定范围完成交付。玻璃命中后显示裂纹与暗色破洞贴图，未命中的原玻璃不变。原生住宅门并非可进入室内的动画门，破洞是视觉模拟，不是对整个 GLB 挖洞。

住宅主投递口距路缘约 3.8 米，配有草坪、短人行路/车库引道、后侧低围栏及树木。道路、导航和碰撞一起更新，不在旧房子上叠新房子。

工业区、商业区、SKYWAY、交通罚款、原生工业库门、多人合作与 2v2 系统继续保留。修正了工业投递判定先被建筑碰撞半径挡住的问题。不会改变旧模型的门外观。

## 操作
电脑 WASD 驾驶，V 进入货箱；步行/货箱 WASD 移动，E 交互，Q 蓄力投掷。先打开后门再从车厢后侧投掷。驾驶状态不显示人物跳跃按钮。手机使用屏幕上的方向、油门、货箱、交互与投掷控件。

## 构建
在完整工程根目录运行 python build.py。脚本校验 src/native-base.html 的 SHA-256，并生成 index.html、VERSION.json、VERSION_V09.json 和 sw.js。若已安装 Node，还会对内联 JavaScript 做语法检查。
主改动在 src/suburban-v011.js；src/viewport-v011.css 与 .js 是唯一视口管理层。不要重新叠加历史的像素高度补丁。
